# 工作台模型设置

## 目标与入口

侧栏新增全局【模型设置】，不依赖已导入的数据集。方向探索、知识挖掘、模型审计的启动区显示当前提供商与模型，并提供前往设置的入口；配置缺失或失效时显示原因并阻止启动。

## 配置行为

1. **提供商管理**：在独立设置入口中复用 DSH 原生提供商配置、模型目录与凭据服务，支持新增、编辑、删除提供商及读取模型。与 DSH 设置管理同一份提供商资料，不复制地址、密钥或模型目录；工作台用途选择独立于 DSH 会话模型。
2. **统一工作台选择**：方向探索、良品知识挖掘、异常知识挖掘、模型审计共用一组提供商及模型引用；DSH 会话继续使用自己的选择。页面和 Agent 工具统一读取工作台配置，Agent 不再用会话模型名覆盖后台选择。挖掘工具的三输入保持不变。
3. **模型能力**：显示实际协议和声明的输入能力；高级设置按需展开容量预检、上下文与输出上限、请求体与视觉输入限制、超时及服务扩展参数。沿用现有模型能力契约，不按型号假定容量或图数，不自动拆组、减张或更换模型。当前视觉链只对已实现的 OpenAI Chat Completions 与 vLLM 容量预检组合开放；其他协议或未知能力明确显示尚不支持，不把 DSH 会话可用当作工业视觉链已验证。
4. **连接检查**：由用户触发，核对模型目录、所选模型和容量接口；不使用数据集图像，不将目录可读描述为视觉分析已验收。失败就地显示原因，保留表单内容。
5. **保存与生效**：工作台选择及能力设置统一保存并带版本检查，保存后用于新作业，无需重启。刷新后保持，提供商或模型被移除后标记引用失效，不静默回退。
6. **冻结执行**：作业启动时冻结提供商、模型、实际地址、协议与有效能力参数；每个作业独立持有执行客户端。后续编辑不改变运行中作业，取消与状态查询继续有效。重试保留原冻结配置；凭据按原引用重新解析，缺失时要求用户处理，不发送到新地址。密钥不进入业务库、作业快照、模型可见输出或提交文件。
7. **现有部署**：将当前本地视觉配置与原生提供商准确匹配后初始化工作台引用；无法唯一匹配时由用户选择。仅迁移本地配置，不把服务器地址、凭据或数据写入仓库；历史作业不补造提供商信息。

## 页面交互

设置页分为【提供商】【任务模型】两区。提供商编辑使用现有共享表单组件，通过 DSH 原生配置和凭据接口保存；工作台模型使用一组紧凑的提供商和模型表单，提供商变化后清空不适用的模型。保存动作集中，显示未保存、保存中、成功与字段错误；高级参数折叠展示。复用现有主题、按钮与控件，支持窄屏纵向布局和键盘操作，不显示数据集选择器或数据集统计。

## 实现边界与外部依据

- 原生目录与提供商解析依据 [DSH LLM 服务](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm/README.md)，配置和凭据沿用宿主服务；独立入口只是同一配置的新访问位置。
- 扩展[模型能力](../../python/iad_core/workbench/model_profile.py)、[执行客户端](../../python/iad_core/workbench/vision.py)及[运行时](../../python/iad_core/workbench/runtime.py)，消除进程内单个环境客户端对所有用途的绑定。页面、HTTP 和 Agent 共享一个工作台模型解析入口。
- 冻结与重试复用[共享作业](../../python/iad_core/workbench/jobs.py)，不由界面直接传密钥或自行拼请求地址。领域契约沿现有生成方式输出到 TypeScript。

## 验收边界

沿现有公开工作台 → HTTP/Python → 真实 SQLite/PIL，以及原生 DSH 浏览器/会话操作；只替换外部 MLLM HTTP 响应。

必须验证：原生提供商管理与独立入口互通；各功能统一命中工作台所选服务、模型和凭据，并与DSH会话选择独立；Agent 与页面一致；保存后刷新与新作业生效；运行中修改不串配置；原冻结配置重试；失效引用、未支持协议和缺少容量时拒绝启动；取消、历史与证据仍可查；密钥不出现在业务持久化和输出中。

真实验收仅在两个已配置服务上使用新合成图和隔离库，覆盖方向探索与知识挖掘的实际路由，保存每次真实调用与结果；不自动重跑生产图像。
