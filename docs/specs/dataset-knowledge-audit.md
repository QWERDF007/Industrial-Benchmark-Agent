# 数据集知识挖掘与证据审计

本文件定义目标行为及验收，不表示功能已经实现。当前实现入口见[架构索引](../architecture.md)，任务依赖见[实施票据](../tickets/dataset-knowledge-audit.md)。

设计输入为用户提供的《审计交互与多维视觉重构》方案包及随后确认的产品原则。原始包本地保留，SHA256：`dec3aa90ee3213f4577c1bb82646b2f764b05059026e2e850c36498ffd83d00b`。包内 UI-S00～UI-S19 的交互与真实性要求纳入下列验收；固定 V/G 检查表、默认框胶 profile、分开的全图/逐 ROI 提示流程由本文件的数据集挖掘与联合审计规则替代。

## 产品原则

知识逐步丰富，常用界面和执行过程保持简洁。产品规则决定检查什么，实际图像与 ROI 证据解释为什么，唯一综合结论指出哪里需要人工复核。MLLM 负责发现产品、结构、允许变化与检查点；不从数据集名称猜测工艺，不内置某种产品的缺陷清单。

## K01 两项可执行技能

交付 `mine-normal-knowledge`（挖掘良品知识）与 `mine-defect-knowledge`（挖掘不良品知识）。它们作为项目插件提供的 DSH 技能被实际注册、发现和调用，具有可分发的说明与执行工具，不是只有 Markdown 的流程描述。

工作台按钮、技能及批量任务共用 Python 领域实现、持久化作业与知识仓储。仅提供数据集、知识版本及可选样本范围即可执行；状态、取消和结果查询共用既有作业能力，不复制第二套状态机或另建站点。

## K02 良品知识挖掘

输入为人工确认良品、选取的参考图及按数据集约定视为初始良品的无标注图。MLLM 联合观察真实全图与必要的原分辨率 ROI，归纳可观察部件、结构关系、外观、允许变化、成像限制及需要检查的位置；按实际上下文容量组织图像组，不把当前参考图的 4/8 张显示限制当作知识挖掘覆盖范围。

挖掘同时寻找候选良品中的异常和矛盾。疑似异常保留原图位置、实际 ROI、理由与来源，进入待核实集合，不再作为该项正常规则的支持证据；不得自动改写原始标签或人工裁决。单例特征、推测和跨样本共识分开记录，不能把偶然异常固化为正常。

验收：非框胶样例能发现自身结构；受污染的无标注良品池能留下可定位疑点；新增光照或合法产品变体可以扩展知识而不把旧异常洗成正常。

## K03 不良品知识挖掘

必须指定可用良品知识版本。输入包括人工异常、有效框/多边形/Mask 标注及 K02 或审计中留下的待核实疑点。MLLM 同时看到全图、真实标注区域与相关正常知识，验证标注所指现象，归纳异常表现、区分条件、正常替代解释及证据限制。

标注类别是线索，不能直接成为缺陷事实；需要保留支持、无法支持和证据不足的验证结果。没有正例证据的可能异常可以保存为待验证假设，不能冒充已验证的不良知识。不能因缺少异常样本而伪造异常类别。

验收：真实异常、错标正常、正常反光和无法判断的区域产生可区分记录；每条异常规则可追溯到正常知识版本及实际支持/反对证据。

## K04 知识快照与持续积累

同一数据集拥有良品和不良品知识，复用同一条目、证据引用及不可变版本机制。条目保留稳定身份、适用对象/位置、可观察判据、正常变化、限制、支持与反对证据、来源资格及状态；不预设固定数量或产品专属的检查项。

不良知识引用其所依据的良品版本。输入图像/标注内容、人工反馈、模型、提示或提炼结构变化后生成后继版本，历史审计仍指向原版本。一次作业冻结知识版本，不能执行到中途切换规则。跨数据集不串用知识。

新审计的发现作为下一次挖掘的候选来源，经过归并与证据核验后扩展后继知识；不在每张图结束后自动把模型建议提升为事实，也不为每张图重复学习整套知识。待审图不能成为其自身结论的唯一正常或异常支持；缺乏独立支持时明确标记。

## K05 框与 Mask 的真实证据

沿用 Labelme 导入、标注仓储与原图像素坐标。支持矩形、多边形及可读取的 Mask，保留掩膜形状和原点，不把 Mask 简化为框后声称已验证其内部像素。

统一证据模块负责几何校验、原图裁剪、掩膜关联/叠加、内容指纹及证据读取。观察区 bbox 与实际送模裁图 crop_bbox 分开；按 ROI 框宽高每侧外扩 20%，边界裁切，必要时无损分块。叠加图须与原始区域图明确区分，不遮盖微小异常；无效、空或错位的几何显式报错。

## K06 规则驱动的联合审计

审计使用冻结的知识版本中适用的检查点规划区域，合并标注、模型候选与细节覆盖；检查点是数据集挖掘结果，不是代码内置的 V01/G01 字典或默认框胶 YAML。

默认一张全图、该图全部计划 ROI、适用正常/异常知识一起送入现有 MLLM，一次联合输出观察与综合建议。一个 ROI 可核验多个检查点，不为每个检查点或 ROI 单独重复发送全图；只有实际上下文不足才分批，新增候选仅按证据缺口追加。执行计划完成不等于排除了所有物理缺陷。

知识不足、不可观察、缺证、未排除的冲突不能转成确定 PASS。保留各次真实输入、原始返回、覆盖和花费；少数关键异常不能被其他正常区域淹没。

## K07 可定位的结论

升级现有 `AuditAnalysis`，不建立平行分析 JSON。模型 finding 指向检查点、原图位置、实际 evidence_ids，包含简短可见现象、异常假设、合理正常解释、限制及复核建议。支持全图级关系疑点，不强行伪造局部框。

`conclusion` 是唯一综合建议；UI 只作投影，默认一句话结论和最多三个优先疑点，点击定位相应 ROI。模型建议、人审、原始数据质量与 Gold 始终保留独立来源。自报置信度和启发式排序分不得显示为缺陷概率或准确率。

## U01 网格与知识入口

保留 DSH 的插件、模型审计、人工复核导航及既有数据集选择。模型审计默认呈现分页网格和少量筛选，取消常驻的长详情栏；缩略图按需读取，返回时保留筛选、页码和滚动位置。

在现有模型审计页面提供数据集知识区，集中放置两项挖掘动作、知识覆盖摘要、待核实数量和“按此知识重审”。知识条目、来源、版本与技术信息按需展开，不新增两个常驻一级面板或迫使用户理解内部编排。

模型状态使用未审计、审计中、无明显异常、发现疑点、证据不足；人审状态独立呈现。保留现有组合标注筛选，并能定位知识挖掘发现的候选异常。

对应输入包 UI-S00、S01、S02、S09、S10、S16。

## U02 大图证据检视器

点击缩略图直接进入同一 DSH 页面的全屏/大面积 dialog。原图为主体，旁侧固定综合摘要及当前 ROI；全图文字、原始记录、路径/UUID/SHA 放入按需区域。大图、ROI 裁图和知识证据共用查看器，不保留两套缩放与坐标逻辑。

标注、模型候选、覆盖区域分层开关；框、多边形和 Mask 都使用原图坐标。悬浮只给短提示，点击或 Enter 锁定；面板反向定位、重叠候选选择、触屏操作、空白取消锁定、Esc 分层退出及关闭后焦点恢复均可用。缩放、拖动、Resize、高 DPR 下坐标和命中一致。

顶部始终显示模型/人审两个来源、覆盖和重点疑点；只展开当前 ROI 的正文与真实送模图。无法回看的证据明确提示，不以原图缩略图或示例图替代。

对应输入包 UI-S03～S08、S11、S12。

## U03 作业、人审与 Agent

知识挖掘与审计作业均明确显示完成、失败、未处理、取消/中断及部分成功。失败可定位到样本，允许只重试失败或未处理项；取消保留已完成结果，不能把剩余任务算为成功。

人审仍只有原有提交入口。切换 ROI 保留输入，切换样本按草稿策略处理，后台作业刷新不覆盖人工决定或输入。

检视器提供携带 dataset/sample/finding/evidence 引用的“向 Agent 追问”入口，在真实 DSH Session 中读取工具图像和解释证据。批量 MLLM 工作流仍由现有领域实现执行；Session 路径须有真实工具/图像轨迹，不能仅跳到空对话或冒充全流程已经由 Agent 执行。技能和追问均不能直接写人审或 Gold。

对应输入包 UI-S13～S16、S18。

## U04 视觉与验收

继承 DSH 明暗主题，以中性色、语义状态、可读字号、8px 间距和清晰焦点保持工业审图密度。优先现有 primitives 和原生交互，避免重型 UI 框架、外部字体依赖及全局覆盖宿主。

已检索 ui-ux-pro-max：Minimalism & Swiss Style、低动效/高密度适用；返回的营销页布局不适用，采用上述 DSH 审图布局约束。键盘焦点与共享选中状态建议可用；不套用检索结果的销售 CTA、轮播或整套品牌色。

验收涵盖 1920×1080、1366×768、1280×800 与窄视口，明暗主题无截断/水平溢出，正文对比度至少 4.5:1，交互目标约 40～44px，尊重 reduced-motion。长文、多 ROI 只按需展示，不能挤占原图。

对应输入包 UI-S17、S19。

## 实现落点与验证接口

- 现有模块入口以[架构索引](../architecture.md)为准。知识挖掘集中到一个 `iad_core.knowledge` 模块，两个技能复用其持久化、证据和作业实现；改造并删除被替代的固定良品模式学习，不并存第二条学习流程。
- Pydantic 定义领域契约，TypeScript 消费从它生成的知识/分析契约；验证来源、类型、证据、版本与坐标。既有用户数据采用有定义的迁移，不捏造新字段对应的模型证据，不删除人审历史。
- 沿用已确认的工作台公开操作链：导入/选参考、启动挖掘或审计、读取作业、读取知识与样本证据、人工提交；真实 SQLite/图像/裁剪，只替换外部 MLLM HTTP。
- DSH 技能需以注册、发现、加载和真实执行结果验证；检视器需以用户操作验证 ROI 命中、左右联动、草稿、返回状态和缩放。不能仅用字符串或截图宣称实现。
- 用至少两个产品形态的受控图像集验证不预置产品规则；包含正常变体、候选良品污染、错标、多边形/Mask、微小异常、逻辑关系、反光、不可判及取消/恢复。
- 真实已授权图像验证链路；效果评估使用人工确认对照集记录召回、误报、定位与缺证识别。缺少人工真值时报告未评估，不以模型自报或模拟响应冒充准确率。
- 开发按切片 TDD 和定向检查，最终统一回归、真实宿主验收、代码评审及提交；本地配置、运行数据和私有输入包不推送。
