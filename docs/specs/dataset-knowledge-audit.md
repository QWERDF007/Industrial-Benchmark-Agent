# 数据集知识挖掘与证据审计规格

本文件为目标行为与验收的唯一规格，不表示已实现。[统一 UI 设计](../design/workbench-ui.md)定义页面布局、视觉与交互，[票据索引](../tickets/dataset-knowledge-audit.md)定义交付依赖，[架构索引](../architecture.md)指向当前实现。

## Problem Statement

数据集管理、浏览、知识准备与模型执行混在模型审计中，用户难以找到独立任务。已有固定良品模式不能表达不同产品的可观察判据、异常证据与来源关系；长文本和孤立区域结论也不便定位复核。用户需要 MLLM 从真实数据逐步学习知识、联合查看全图与局部证据，并在统一界面完成浏览、挖掘、审计和人工裁决。

## Solution

以共享数据集贯穿六个并列入口：图像浏览、数据集管理、挖掘良品知识、挖掘不良品知识、模型审计、人工复核；两项挖掘位于模型审计之前。两项真实 DSH 技能与页面按钮执行同一领域操作。知识经证据核验后形成不可变版本，审计冻结版本并联合输入全图与全部适用 ROI；简洁结果可直接定位证据和人工复核。

知识逐步丰富，常用界面和执行过程保持简洁。MLLM 发现产品结构、正常变化与检查点，不从名称猜工艺、不内置某产品缺陷清单。产品规则决定检查什么，真实图像解释为什么，唯一综合建议指出需要复核的位置。

## User Stories

1. 作为操作员，我希望在侧栏直接进入六项业务，以便不必从模型审计寻找浏览、管理和知识准备。
2. 作为操作员，我希望页面共享所选数据集，以便切换业务时不会分析错对象。
3. 作为操作员，我希望刷新、后退与跨页跳转恢复上下文，以便继续当前样本。
4. 作为数据管理员，我希望选择图像目录和标注目录导入 Labelme，以便保留原有目录结构与标注。
5. 作为数据管理员，我希望编辑数据集显示名称，以便识别业务而不破坏稳定身份。
6. 作为数据管理员，我希望调整无标注初始良品约定与参考资格，以便纠正不适用的默认来源。
7. 作为审图员，我希望把有无标注和类别放在同一多选菜单，以便组合筛选样本。
8. 作为审图员，我希望模型、人审、技术问题分别筛选和显示，以便理解不同来源。
9. 作为审图员，我希望点缩略图进入大图并原位返回，以便连续查看大量样本。
10. 作为操作员，我希望独立启动良品知识挖掘并查看来源覆盖，以便建立该产品的正常规律。
11. 作为操作员，我希望候选良品中的异常被隔离为待核实，以便不把污染学成正常规则。
12. 作为操作员，我希望知识区分共识、单例和推测，以便了解支持程度。
13. 作为操作员，我希望挖掘时保留正常结构、位置、光照与允许变化，以便识别真实偏离。
14. 作为操作员，我希望依据指定良品版本挖掘异常知识，以便建立可比较的异常判据。
15. 作为标注核验员，我希望 MLLM 验证框、多边形和 Mask 指向的真实现象，以便发现错标。
16. 作为标注核验员，我希望保留反光等正常解释和无法判断结果，以便不把标签当成真值。
17. 作为操作员，我希望查看每条知识的支持、反对和原始证据，以便判断其适用性。
18. 作为操作员，我希望新来源生成后继知识版本，以便继续积累而能追溯历史审计。
19. 作为操作员，我希望一项作业固定使用同一知识版本，以便结果在批次内可比较。
20. 作为操作员，我希望默认审计当前筛选的全部图像与全部计划 ROI，以便不因任意预算漏检。
21. 作为审图员，我希望全图、所有 ROI 与知识一起交给 MLLM，以便结构、位置和局部现象得到联合解释。
22. 作为审图员，我希望只在实际上下文不足时拆批，以便减少重复请求并保留跨区域关系。
23. 作为审图员，我希望缺证、冲突和不可观察被明确指出，以便不会收到虚假的确定 PASS。
24. 作为审图员，我希望一句综合建议关联少量优先疑点，以便迅速找到需人工检查的位置。
25. 作为审图员，我希望点 ROI 和点证据列表可以相互定位，以便核对结论与原图。
26. 作为审图员，我希望滚轮和比例按钮缩放不跳位，以便检查微小异常。
27. 作为审图员，我希望用可视图标控制标注、模型和覆盖图层，以便区分实际证据与覆盖规划。
28. 作为操作员，我希望每张审计完成后及时更新界面，以便无需等待全批次。
29. 作为操作员，我希望取消、失败、中断和未处理数量准确，以便决定重试范围。
30. 作为操作员，我希望只重试失败或未处理项且保留已完成结果，以便避免重复消耗。
31. 作为复核员，我希望只有人工复核提供裁决表单和复核明细，以便业务入口清晰。
32. 作为复核员，我希望切 ROI、切页、刷新结果时保留未提交草稿，以便输入不丢失。
33. 作为复核员，我希望模型建议与人工结果分开，以便建议不会冒充自己的决定。
34. 作为复核员，我希望携带当前证据向真实 DSH Agent 追问，以便进一步验证解释。
35. 作为 Agent 使用者，我希望两项挖掘技能可发现、加载和执行，以便获得与页面一致的知识结果。
36. 作为操作员，我希望不同页面在明暗主题、键盘和窄屏中一致可用，以便长期连续操作。
37. 作为维护者，我希望共享契约、证据、作业和写入入口，以便避免两套实现逐渐分叉。
38. 作为验收者，我希望真实 MLLM 验证与人工真值评估分开记录，以便不把模拟响应或自报置信度当成准确率。

## Implementation Decisions

### U01 独立导航与共享工作台

六项业务入口、页面职责、上下文与统一视觉以 UI 设计 D01～D06 为唯一依据。图像浏览、数据集管理和两项知识挖掘均不再是模型审计内页签。复用宿主侧栏和页面生命周期，一套页面壳、数据集上下文、图像查询与证据检视器支持六页，禁止复制六份工作台。

图像浏览是跨流程只读入口；模型审计可呈现审计结果网格，但不复制管理、知识编辑或人审表单。跨页操作携带数据集、样本与版本引用，返回保留原状态。

### K01 两项可执行技能

交付 `mine-normal-knowledge`（挖掘良品知识）与 `mine-defect-knowledge`（挖掘不良品知识）。它们作为项目插件提供的 DSH 技能被实际注册、发现和调用，具有可分发的说明与执行工具，不是只有 Markdown 的流程描述。

工作台按钮、技能及批量任务共用 Python 领域实现、持久化作业与知识仓储。仅提供数据集、知识版本及可选样本范围即可执行；状态、取消和结果查询共用既有作业能力，不复制第二套状态机或另建站点。

### K02 良品知识挖掘

输入为人工确认良品、选取的参考图及按数据集约定视为初始良品的无标注图。MLLM 联合观察真实全图与必要的原分辨率 ROI，归纳可观察部件、结构关系、外观、允许变化、成像限制及需要检查的位置；按实际上下文容量组织图像组，不把当前参考图的 4/8 张显示限制当作知识挖掘覆盖范围。

挖掘同时寻找候选良品中的异常和矛盾。疑似异常保留原图位置、实际 ROI、理由与来源，进入待核实集合，不再作为该项正常规则的支持证据；不得自动改写原始标签或人工裁决。单例特征、推测和跨样本共识分开记录，不能把偶然异常固化为正常。

验收：非框胶样例能发现自身结构；受污染的无标注良品池能留下可定位疑点；新增光照或合法产品变体可以扩展知识而不把旧异常洗成正常。

### K03 不良品知识挖掘

必须指定可用良品知识版本。输入包括人工异常、有效框/多边形/Mask 标注及 K02 或审计中留下的待核实疑点。MLLM 同时看到全图、真实标注区域与相关正常知识，验证标注所指现象，归纳异常表现、区分条件、正常替代解释及证据限制。

标注类别是线索，不能直接成为缺陷事实；需要保留支持、无法支持和证据不足的验证结果。没有正例证据的可能异常可以保存为待验证假设，不能冒充已验证的不良知识。不能因缺少异常样本而伪造异常类别。

验收：真实异常、错标正常、正常反光和无法判断的区域产生可区分记录；每条异常规则可追溯到正常知识版本及实际支持/反对证据。

### K04 知识快照与持续积累

同一数据集拥有良品和不良品知识，复用同一条目、证据引用及不可变版本机制。条目保留稳定身份、适用对象/位置、可观察判据、正常变化、限制、支持与反对证据、来源资格及状态；不预设固定数量或产品专属的检查项。

不良知识引用其所依据的良品版本。输入图像/标注内容、人工反馈、模型、提示或提炼结构变化后生成后继版本，历史审计仍指向原版本。一次作业冻结知识版本，不能执行到中途切换规则。跨数据集不串用知识。

新审计的发现作为下一次挖掘的候选来源，经过归并与证据核验后扩展后继知识；不在每张图结束后自动把模型建议提升为事实，也不为每张图重复学习整套知识。待审图不能成为其自身结论的唯一正常或异常支持；缺乏独立支持时明确标记。

### K05 框与 Mask 的真实证据

沿用 Labelme 导入、标注仓储与原图像素坐标。支持矩形、多边形及可读取的 Mask，保留掩膜形状和原点，不把 Mask 简化为框后声称已验证其内部像素。

统一证据模块负责几何校验、原图裁剪、掩膜关联/叠加、内容指纹及证据读取。观察区 bbox 与实际送模裁图 crop_bbox 分开；按 ROI 框宽高每侧外扩 20%，边界裁切，必要时无损分块。叠加图须与原始区域图明确区分，不遮盖微小异常；无效、空或错位的几何显式报错。

### K06 规则驱动的联合审计

审计使用冻结的知识版本中适用的检查点规划区域，合并标注、模型候选与细节覆盖；检查点是数据集挖掘结果，不是代码内置的 V01/G01 字典或默认框胶 YAML。

默认一张全图、该图全部计划 ROI、适用正常/异常知识一起送入现有 MLLM，一次联合输出观察与综合建议。一个 ROI 可核验多个检查点，不为每个检查点或 ROI 单独重复发送全图；只有实际上下文不足才分批，新增候选仅按证据缺口追加。执行计划完成不等于排除了所有物理缺陷。

知识不足、不可观察、缺证、未排除的冲突不能转成确定 PASS。保留各次真实输入、原始返回、覆盖和花费；少数关键异常不能被其他正常区域淹没。

### K07 可定位的结论

升级现有 `AuditAnalysis`，不建立平行分析 JSON。模型 finding 指向检查点、原图位置、实际 evidence_ids，包含简短可见现象、异常假设、合理正常解释、限制及复核建议。支持全图级关系疑点，不强行伪造局部框。

`conclusion` 是唯一综合建议；UI 只作投影，默认一句话结论和最多三个优先疑点，点击定位相应 ROI。模型建议、人审、原始数据质量与 Gold 始终保留独立来源。自报置信度和启发式排序分不得显示为缺陷概率或准确率。

### U02 大图证据检视器

知识、参考图和审计复用一个真实证据检视器，坐标使用原图像素，不能用示例图或普通缩略图代替送模证据。交互、图层、布局与焦点规则见 UI 设计 D04。finding、当前 ROI 和实际证据必须可双向定位，全图关系疑点可没有局部框。

### U03 作业、人审与 Agent

知识挖掘与审计作业均明确显示完成、失败、未处理、取消/中断及部分成功。失败可定位到样本，允许只重试失败或未处理项；取消保留已完成结果，不能把剩余任务算为成功。

人审仍只有原有提交入口。切换 ROI 保留输入，切换样本按草稿策略处理，后台作业刷新不覆盖人工决定或输入。

检视器提供携带 dataset/sample/finding/evidence 引用的“向 Agent 追问”入口，在真实 DSH Session 中读取工具图像和解释证据。批量 MLLM 工作流仍由现有领域实现执行；Session 路径须有真实工具/图像轨迹，不能仅跳到空对话或冒充全流程已经由 Agent 执行。技能和追问均不能直接写人审或 Gold。

对应输入包 UI-S13～S16、S18。

### U04 视觉与交互来源

UI 设计 D01～D06 是导航、状态保存、六页布局、大图操作、视觉 tokens、反馈和响应式验收的唯一详细定义。领域知识、结论与版本事实从后端读取，前端不维护另一套事实。当前 DSH 主题和 React 18 是实施约束，不因设计检索而更换宿主或升级框架。

### A01 模块与写入边界

沿用架构索引中的注册、查询、证据、审计、人审及桥接边界。知识挖掘集中到一个领域模块；两项技能、工作台和批量执行共用知识仓储及持久化作业。先建立最小贯通切片，再逐步替换并删除固定良品模式学习，不长期并存两条学习流程。

Pydantic 是知识与分析契约唯一来源，TypeScript 使用生成结果。升级现有分析模型，不创建平行版本 JSON；一个正常/异常知识仓储通过类型区分，不创建两套版本状态机。人审和 Gold 原有写入边界保持唯一。

### A02 数据与版本契约

知识快照关联 dataset、kind、version、parent、所依据良品版本、模型与提示/schema版本、输入指纹、条目、支持/反对证据及覆盖。知识版本内容不可变，当前版本引用原子更新。未完成或失效输入不能发布为可用完整知识；部分产物可诊断回看但不得冒充全部覆盖。

作业保留请求范围、冻结输入与版本、逐样本结果、错误、当前阶段、父重试关系和时间。重试创建关联的新执行，原记录不重写；显式恢复核验来源与知识版本，变化时要求重启，不静默混入新输入。

历史用户数据采用明确迁移，不删除人工记录、不捏造 findings 或知识支持证据。历史样本身份保留关联，面向用户显示稳定 UUID；历史模型建议缺少新知识引用时如实标记。目录、标签或旧六域模式不得无证据地升级为已核实知识。

### A03 操作契约

沿用工作台公开操作链，增加按数据集/类型启动挖掘、读取知识版本/条目/证据、查询与取消/重试共享作业、选择冻结知识启动审计。请求范围默认为全部符合条件的候选，支持显式子集；知识输出不依赖参考缩略图显示数量。

服务器校验样本归属、知识类型/版本关系、实际证据访问与状态迁移。相同活动作业不能重复启动；取消返回停止请求而非假称外部推理已终止。多页共享低频上下文，异步结果按 dataset/sample/job 身份更新，不覆盖草稿或图像视口。

知识陈旧分为来源变化与正常/异常版本关系变化。审计启动前显示所选冻结版本及提醒，历史版本仍可追溯。缺少良品知识时引导挖掘；没有异常样本时允许基于良品的异常筛查，输出必须说明异常知识缺失。

## Testing Decisions

1. 沿用用户已确认的最高公开边界：导入/选参考 → 页面或技能启动挖掘 → 查询作业与知识/证据 → 启动审计 → 图像检视 → 人工提交。真实 SQLite、真实图像和真实裁剪，只替换外部 MLLM HTTP；不 mock 内部知识、证据、仓储或作业协作。
2. 每票按一次完整用户操作先写失败测试，再实现至通过；开发中只跑相关定向检查，完成后统一回归。此前工作台、HTTP 桥接和 Firefox 流程作为既有测试先例，入口由架构索引指向。
3. 两种以上非特定工艺的受控产品集覆盖正常变体、初始良品污染、错标、矩形/多边形/Mask、微小异常、位置/逻辑关系、反光与不可判。验证模型输入的真实证据、外扩像素、版本冻结、自我支持排除、跨数据集隔离及异常先验缺失。
4. 容量测试验证默认一张全图加全部 ROI 的联合请求，实际不足才拆批，缺证/冲突不产生确定 PASS。HTTP 替身返回业务结果，不能返回 schema 再自证解析成功。
5. 实际宿主验证技能注册、发现、加载、执行及知识可见；Agent 追问验证真实 Session、工具读取和图像轨迹。普通批处理不能冒充 Agent 行为。
6. 浏览器验证全部六入口、改名/切数据集、刷新/后退/深链、筛选并集、作业逐图更新、ROI 命中/缩放/图层/键盘、草稿及唯一人审入口。UI 设计 D06 规定的视口、明暗、文字放大和焦点条件都需实测。
