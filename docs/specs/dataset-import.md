# Labelme 与图像级异常检测数据集统一接入规格

## Problem Statement

用户需要在同一个 MLLM 工作台管理带真实区域标注的 Labelme 数据，以及由父目录下 OK、NG 等子目录提供图像级标签的数据。当前公开导入要求图像目录和 Labelme 标注目录，已有目录适配能力没有贯通页面、Agent、知识来源和审计报告。

没有矩形、多边形或掩膜，不等于没有图像标签。若继续按无区域标注处理，NG 图可能进入正常知识池；若异常来源只认区域标注，无框 NG 又无法直接参与不良知识挖掘。用户还需要发现目录错标、调整映射后重新核验，并在各侧栏页面追踪真实进度与历史。

## Solution

添加数据集弹窗提供 Labelme、异常检测目录两种格式。后者填写名称和服务器父目录，经过真实扫描预览、目录角色映射和校验后导入。目录角色为正常、异常、未标记或排除。两类数据复用身份、扫描、知识版本、MLLM 全图与局部联合审计、人工复核及质量报告。

OK/NG 是可被核验的原始图像标签，不代替视觉证据、人工裁决或 Gold。明确 OK 产生正常候选，明确 NG 产生异常候选；未知目录不自动变成良品。审计先进行屏蔽待审图标签的视觉判断，再对照目录标签呈现不一致。页面与 DSH 对话使用同一领域入口。

## User Stories

1. 作为数据管理员，我希望选择格式，以便接入 Labelme 或目录图像级数据。
2. 作为数据管理员，我希望 Labelme 支持独立图像、标注目录，以便复用已有数据。
3. 作为数据管理员，我希望图像级格式只填写父目录，以便不必构造空 JSON。
4. 作为数据管理员，我希望名称默认取目录名且可编辑，以便快速识别业务数据。
5. 作为数据管理员，我希望查看真实目录预览，以便确认扫描范围。
6. 作为数据管理员，我希望常见 OK/NG 别名产生建议，以便减少配置操作。
7. 作为数据管理员，我希望映射任意目录名，以便接入非标准结构。
8. 作为数据管理员，我希望递归读取已分配目录，以便保留批次层级。
9. 作为数据管理员，我希望保留未知目录为未标记，以便稍后核验。
10. 作为数据管理员，我希望显式排除目录，以便控制分析范围。
11. 作为数据管理员，我希望发现重叠和冲突规则，以便避免同图多重标签。
12. 作为数据管理员，我希望根目录直属图像按未标记处理，以便系统不猜测质量。
13. 作为数据管理员，我希望只导入 OK 或只导入 NG，以便先接入再补来源。
14. 作为数据管理员，我希望同名文件按相对路径区分，以便不同子目录样本不被覆盖。
15. 作为数据管理员，我希望保留 train/test 结构，以便接入不改变原有划分。
16. 作为数据管理员，我希望预览与导入数量有明确口径，以便区分发现文件和成功图像。
17. 作为数据管理员，我希望空目录、无权限和坏图得到真实反馈，以便定位问题。
18. 作为数据管理员，我希望重复来源被识别，以便复用已有数据集身份。
19. 作为数据管理员，我希望失败不留下半套数据，以便修正后重试。
20. 作为操作员，我希望卡片显示格式适用的数量，以便不把图像标签当区域标注。
21. 作为操作员，我希望分开查看原始标签、模型建议和人工结果，以便理解来源。
22. 作为操作员，我希望按 OK、NG、未标记筛选，以便检查特定集合。
23. 作为操作员，我希望区域标注筛选只在适用时显示，以便减少无效控件。
24. 作为操作员，我希望卡片保持统一简洁，以便浏览时不堆积标签。
25. 作为操作员，我希望修改目录角色后预览重扫，以便纠正错标映射。
26. 作为操作员，我希望重扫保留同路径 UUID 和人工记录，以便连续工作。
27. 作为操作员，我希望改名不导致知识失效，以便不触发无关计算。
28. 作为知识维护者，我希望只有明确正常候选进入正常池，以便 NG/未知图不被学成正常。
29. 作为知识维护者，我希望无框 NG 进入异常候选，以便学习异常外观。
30. 作为知识维护者，我希望人工正常/异常决定优先决定来源资格，以便修正错标。
31. 作为知识维护者，我希望不确定/跳过不冒充确认资格，以便避免错误支持证据。
32. 作为知识维护者，我希望模型验证 NG 的视觉依据，以便错标不变成异常知识。
33. 作为知识维护者，我希望来源和规则变化可追溯，以便判断知识是否需更新。
34. 作为审图员，我希望全图与原分辨率细节一起分析，以便理解整体局部关系。
35. 作为审图员，我希望无区域标注仍覆盖必要细节，以便检查小异常。
36. 作为审图员，我希望必要时追加模型提议的 ROI，以便补齐真实缺证。
37. 作为审图员，我希望原始框、覆盖分块、模型 ROI 可区分，以便不误认为都具有人工区域真值。
38. 作为审图员，我希望审计输入不暴露待审图标签，以便减少目录语义诱导。
39. 作为审图员，我希望标签不一致形成复核线索，以便发现目录标签问题。
40. 作为审图员，我希望模糊、反光和缺证保留不确定，以便不被迫得到 PASS/FAIL。
41. 作为操作员，我希望逐图更新成功、失败和未处理数量，以便了解真实进度。
42. 作为操作员，我希望恢复核验冻结标签与知识，以便不混用新旧输入。
43. 作为复核员，我希望人工复核是唯一人工裁决入口，以便建议不会直接写 Gold。
44. 作为复核员，我希望修改后仍可查看旧知识和证据，以便解释历史决定。
45. 作为报告使用者，我希望看到标签分布与审计覆盖，以便了解适用范围。
46. 作为报告使用者，我希望不一致比例明确分母，以便区分确定冲突和未完成核验。
47. 作为报告使用者，我希望一致性不被称为准确率，以便不把自带标签当独立真值。
48. 作为 Agent 使用者，我希望一句服务器目录说明就能发起流程，以便无需先手工建数据集。
49. 作为 Agent 使用者，我希望只在真实歧义时被追问，以便减少重复配置。
50. 作为 Agent 使用者，我希望会话与页面查看同一执行，以便往返查看和修改。
51. 作为键盘或窄屏用户，我希望格式切换、映射和弹窗均可操作，以便完成导入。
52. 作为维护者，我希望所有入口共享类型、资格与写入口，以便不产生两套实现。

## Implementation Decisions

### A01 统一架构与现有能力

沿用 DSH Web 唯一宿主、TypeScript 原生插件、Python 领域核心和 SQLite。六个固定入口仍为数据集管理、图像浏览、挖掘良品知识、挖掘不良品知识、模型审计、人工复核。新格式不另建页面、作业状态机或训练系统。Pydantic 定义领域契约并生成 TypeScript 投影。

先把已有 Labelme 导入整理为显式格式契约，再让目录格式消费同一接口；必要的组件与契约整理随首个真实切片交付，不额外构建泛化框架。现有 Labelme 矩形/多边形/Mask、知识与人审数据通过明确迁移保留语义，不伪造区域或丢失历史。

### A02 格式与操作契约

导入使用判别联合。`labelme` 要求名称、图像目录和标注目录；`folder_classification` 要求名称、根目录和确认的目录角色规则。名称沿用长度和空白校验。图像级分支不接受标注目录或无标注初始良品开关。

| 操作 | 输入与输出语义 |
| --- | --- |
| 预览 | 格式、根目录、可选映射 → 实际目录、图像数、角色建议、冲突、范围和预览指纹；不登记数据 |
| 导入 | 格式化配置和确认范围 → 校验后原子发布、稳定身份及实际成功/失败数量 |
| 查询 | 返回格式、适用目录、标签/区域统计及来源，页面与 Agent 共用结果 |
| 重扫 | 既有身份和可选规则变更 → 预览后更新当前投影，不重写旧证据或自动启动模型 |
| 知识/审计/报告 | 复用既有操作，扩展资格、冻结指纹、标签对照和依赖状态 |

HTTP、DSH 工具与页面共用领域入口。路径、格式与角色规则校验由后端执行，前端只提供交互与投影；Agent 不在提示词中另写目录解析器。

### A03 目录规则与扫描

| 角色 | 原始状态 | 导入行为 |
| --- | --- | --- |
| 正常 | PASS，界面显示 OK | 递归导入为正常候选 |
| 异常 | FAIL，界面显示 NG | 递归导入为异常候选 |
| 未标记 | UNCERTAIN | 导入，默认不进入正常/异常来源池 |
| 排除 | 不产生样本标签 | 不导入 |

`OK/good/normal`、`NG/bad/abnormal/anomaly/defect` 仅按完整目录名、忽略大小写产生建议，不做子串、文件名或非 OK 即 NG 推断。自定义名称通过显式映射。预览使实际规则可见，保存后按根目录下相对目录规则扫描，不在重扫时重新猜测。

每图只有一个角色。同目录多角色、嵌套规则重叠、OK/NG 祖先语义冲突必须在预览解决。根目录直属图像及未匹配图像默认未标记，可显式排除。保留批次、train/test 和相对路径；不同子目录同名图不冲突。NG 下级目录名不自动变成已核实缺陷类别。

支持单类和未知数据。无合格正常来源时允许导入/浏览/复核，依赖正常知识的操作提示补来源；无异常候选时跳过不良知识，可依据正常知识筛查。

仅扫描确认范围内的受支持图像。拒绝越界、不可访问路径和冲突；坏图产生真实问题，图像级缺少 JSON 不产生缺标注警告。重复来源检查跨两格式，相同图像根目录不以不同映射再次登记，复用既有身份维护来源。

预览区分发现文件数与成功导入数，记录规则和文件范围指纹。提交重新校验，范围变化要求刷新预览，不静默导入未确认分布。扫描复用临时结果与事务发布，失败保留原状态。预览缓存不成为第二份标签事实。

### A04 标签事实与身份

样本现有质量状态及来源承载导入图像标签，角色规则属于数据集配置，扫描发布当前样本标签。不在区域表复制 OK/NG，不生成整图假框。原始图像标签、区域标注、模型建议、人工决定和 Gold 保留独立来源。

人审 PASS/HARD_NORMAL 提供正常资格，人审 FAIL 提供异常资格；人工不确定或跳过不充当确认来源。人工结果影响资格，不覆盖原始标签。无人审时按明确原始 OK/NG 产生候选。目录格式禁止因区域数为零自动视为良品，手动选取不得绕过资格校验。Labelme 初始无标注约定继续限于原有格式语义。

同数据集同相对路径重扫保留 UUID 和人工记录，改映射不改身份。移动文件导致路径变化沿用现有身份规则，不承诺自动迁移历史。已有数据集不原位切换格式。

### A05 导入与管理界面

添加弹窗用格式单选切换必要字段。Labelme 填名称和两目录；目录格式填名称与根目录，默认名称来自目录名。紧凑预览列出目录、图像数、角色；冲突就地显示，解决后才能提交。错误保留输入，预览不登记数据。

保留现有宽卡片区、右侧窄详情、面板背景与桌面铺满高度，窄屏自然上下排列。卡片显示名称、图像数和适用统计：Labelme 显示真实区域数，目录格式显示明确图像标签数，未标记不计为明确标签。详情名称下一行为 ID，再显示格式、数量、目录与映射。名称沿用回车/失焦按变更保存、Esc 取消；删除仍为右上角同尺寸无边框图标、确认默认取消，保留服务器源文件。

规则修改先预览再显式保存并重新扫描，显示影响范围和真实结果。改名不触发来源失效。沿用宿主明暗主题、共享按钮/选择器/表单/弹窗和焦点逻辑，减少说明文字，不复制页头统计。

### A06 图像浏览与复核

原始图像标签 OK/NG/未标记提供独立多选，同组为并集，不同维度为交集。区域标注有无/类别仍属于真实区域维度，目录格式隐藏不适用菜单；模型和人工筛选独立存在。

缩略图保持等尺寸、左上角颜色方块、简短 Tooltip、文件名及并排技术分/模型分，不再堆目录标签。详情分开显示原始标签及来源、模型综合建议、人工决定。共用查看器保持遮罩/右上角关闭、滚轮与中心缩放、可视图层、全图/ROI 联动及焦点恢复，目录格式不绘制不存在的标注。

人工裁决与明细只有人工复核入口，保留草稿与历史。目录/模型不一致形成复核线索，不自动改标签或写 Gold。

### A07 知识来源与版本

两项挖掘共用来源仓储与版本机制。明确 OK 是正常候选，无区域的明确 NG 是导入异常候选；人审优先、不可用图与污染隔离在统一资格规则执行。异常挖掘必须引用同数据集可用正常版本。NG 仅提供候选身份，MLLM 须从真实图像给出支持、反对、正常替代解释和限制，看不出异常时保留不确定或标签可疑。

冻结输入包含图像内容、原始标签、实际匹配规则语义、人工反馈与资格，变化可检测；名称等无关元数据不进入内容失效判定。历史知识不可变，后继版本保留关系；核实反馈作为输入重新验证，不直接改写已发布知识。

### A08 联合审计与标签屏蔽

继续基于 MLLM：正常知识先形成可追溯判据，再与新图全图、全部计划细节联合分析，关联结构、位置、光照和合理变化。无区域标注时用原分辨率覆盖分块；必要时模型提出位置并追加裁剪。真实导入 ROI 沿用按框宽高各外扩20%的规则，覆盖块不伪装成导入框。

上下文足够时多图一次输入，按含图 token 的实际容量组织，不足才分批并带图综合。默认审计当前筛选全部图像、全部适用细节，不恢复人为图像数/ROI预算。覆盖块、模型 ROI、原始区域保留不同来源及原图坐标。

待审图的 OK/NG、含标签目录/文件名及等价字段不能进入审计请求；送模文本、证据描述与标识使用中性引用，本地保留映射。知识学习可知道来源角色，审计当前图不带预期答案。先持久化模型建议，再由系统对照原始标签。

自身或同内容副本不能作为唯一独立知识支持。未知、不可观察、未解冲突或缺证保留 UNCERTAIN；没有人工区域本身不算缺证。每图一份综合建议，疑点关联实际证据，不从分块另造互相孤立的结论。

### A09 作业、修改与历史

作业冻结范围、来源标签/规则与知识版本，逐图显示完成/失败/未处理。取消保留完成结果，重试关联新执行且只补未完成审计；来源或冻结知识变化时拒绝混合恢复，提示新知识/新作业，不靠默认 PASS 或重复数据兜底。

重扫只发布输入变化，不自动重跑 MLLM。知识页显示变化原因，审计页可明确选择后继版本重审，报告显示适用版本和范围。旧图像证据、分析和人工历史可查；会话与六步骤页面共享执行、结果和允许的修改。

### A10 标签对照与质量报告

保留技术可用率、审计覆盖率、人工核验覆盖率，分别显示分子/分母、时间、知识版本和范围，不计算未校准总分。

增加原始与已审计 OK/NG/未标记分布、不一致线索。不一致比例分母仅包含原始明确 OK/NG 且最新模型建议明确 PASS/FAIL 的可比较样本；每样本只取范围内适用的最新记录。原始未标记、模型 UNCERTAIN、失败和未审计单列，零分母为未评估。原始标签/规则在审计后变化时标示来源变化，不把旧记录伪装成核验新标签的结果。

目录标签对照不是独立准确率，模型置信度不是缺陷概率。无区域真值不算 IoU 或分割/检测准确率。全来源参与知识学习后的审计属于数据质量核验，不宣称独立测试集表现。

### A11 DSH 会话流程

用户只给父目录时 Agent 先读取实际结构和格式候选；明确 OK/NG 规则或唯一无歧义建议可沿已有授权继续，自定义角色、多格式候选或矛盾映射只追问真实歧义。名称默认取目录名，不编造路径或声称上传。

Agent 使用页面相同的预览/导入/重扫/资格入口，依次取得正常知识、实际可用异常知识、冻结审计与统一报告。无异常来源如实跳过，缺正常来源停在需补来源的步骤。运行中不声称完成，部分失败如实报告；工具卡打开同一数据集/作业/知识/证据，追问读取真正送模的冻结图像。

## Testing Decisions

### T01 主要边界

沿用公开工作台操作链：预览/导入/查询/重扫/来源/知识/审计/复核/报告穿过真实 HTTP、Python bridge、领域服务、临时 SQLite 与合成图像文件。断言外部行为、实际记录和来源，不断言私有 Helper、SQL 排列或组件状态。只在更深层替换外部 MLLM HTTP 响应，不 mock 注册、扫描、仓储、资格、作业或人审。

沿用既有来源/删除隔离、知识污染/反馈、提示屏蔽、报告分母和恢复测试的真实资源模式。少量领域定向测试覆盖浏览器难以稳定制造的规则冲突与原子发布，仍涉及下一层依赖。每票先失败测试再实现，开发期不运行全量。

### T02 验收矩阵

| 范围 | 必测外部行为 |
| --- | --- |
| 两格式 | Labelme 矩形/多边形/Mask 保持；目录 OK/NG/未知/单类/根直属/递归同名；真实预览与编辑 |
| 拒绝与事务 | 空/坏/无权限目录、冲突/重叠/越界、重复根、预览后变化、失败无半提交、删除保留源文件 |
| 当前投影 | 数量、标签筛选、分页选择、卡片简洁、目录详情、改名/重扫、身份与历史 |
| 知识资格 | NG/未知不入正常池、无框NG可挖掘、人审优先、不确定不冒充确认、污染隔离 |
| 冻结恢复 | 内容/标签/规则变化可见、改名不失效、旧输入恢复拒绝混合、失败保留成功历史 |
| 视觉判断 | 捕获实际送模请求验证无标签泄漏；全图/分块/ROI联合、真实像素及坐标 |
| 报告 | 三项口径、确定一致/不一致、不确定/失败/未审计、零分母、来源变化，不输出虚假准确率 |

### T03 原生入口与真实环境

沿用真实浏览器与原生 DSH，验证格式切换、预览、筛选、模态初始/恢复焦点、遮罩、键盘、明暗、窄屏、文字放大和图像交互。原生会话从自然语言触发工具、技能与附件，不能以手工顺序调工具冒充完整 Agent。该验收验证另一入口连接，不复制领域测试体系。

真实 MLLM 只用新生成合成 OK/NG/未知/错标图、隔离库和脚本自身作业；验证传输、结构、证据、版本和恢复，不改生产数据或宣称工业准确率。服务须支持多图、含视觉 token 的预检及随后同图生成。

## Out of Scope

- 浏览器上传、ZIP 上传入口；现有无关接口不因文档清理而删除。
- 新训练系统、替换 MLLM、自动修改生产模型部署。
- 自动划分 train/val/test、自动赋予NG下级目录缺陷类别、跨产品混合学习。
- 生成区域真值、检测/分割指标、独立分类基准或业务加权总分。
- 数据集原位切换格式、移动文件自动迁移身份、自动改原始标签/人审/Gold。
- 新侧栏业务、新主题体系、重复写入口或兼容两套导入状态机。
