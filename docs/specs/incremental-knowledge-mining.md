# MLLM 图组知识挖掘与统一工作台规格

## Problem Statement

用户需要在 DSH 会话分别触发导入数据、良品知识挖掘、异常知识挖掘和模型审计。现有完整流程指引容易使 Agent 在仅要求导入时继续挖掘全部来源；这是任务范围错误，不能用“标准流程”解释成用户授权。

用户希望工具保持简单：提供可选知识预设、图像数量和对应图像，就能完成一次图组挖掘。先看较多图归纳知识、之后结合已有知识看较少新图，是 Agent 根据上下文连续调用工具的方式，不应变成工具的首批/后续参数或固定批次策略。现有隐式并入全部历史来源、容量不足后独立拆批再汇总的流程不能完整表达这种知识续用。

用户要求持续挖掘整个范围时，20 张表示每次取图数量，不能被当作总量后提前结束。期望链路为“首组图 → V1 → 下一组图＋V1 → V2 → 持续处理剩余图像”。新图可能揭示旧知识不完整，也可能是良品池中的异常；模型不能自行选定哪一方错误，须将涉及的知识、图像或局部区域关联标记，保留证据等待人工确认。

用户还需要一个统一的知识挖掘侧栏页面，选择图组、查看知识与整图/局部疑点，并追踪真实执行状态。整个项目基于 MLLM，但不得预设模型厂商、名称、上下文长度、每请求图数、协议扩展或超时值；支持多图和容量可容纳，也不等于知识可靠或能够检出所有异常。

## Solution

侧栏保留数据集管理、图像浏览、知识挖掘、模型审计、人工复核五个入口。知识挖掘页面内切换良品/异常，复用相同的预设、数量、选图、结果和作业交互；知识类型、来源资格和版本仍有明确区分。

保留两个直接工具：`knowledge_mine_normal` 与 `knowledge_mine_defect`。它们均只接受可选知识预设、图像数量和对应图像三个业务输入。Agent 根据已知上下文决定是否附带预设，工具只处理给定图组；页面使用同一契约和领域入口。一次调用产生一份不可变知识结果、变化记录和可回溯疑点，后续调用可显式续用该结果。

按用户实际要求选择阶段；仅导入就完成导入并停止。完整数据质量流程只有在用户要求时才执行。模型和服务能力由运行配置及实际能力校验决定；大图、真实 ROI 和必要比较证据共同参与分析，按用户确认数量联合输入完整图组；容量或调用失败后等待用户决定是否降低数量，不自动拆组、减张或重试。

连续范围、版本推进与终止条件见 A11；冲突关联、隔离和人工确认见 A15、A16。单组完成、范围观察完成及人工确认完成分别报告，不合并成一个“成功”。

## Implementation Decisions

### A01 任务范围与提示词职责

项目系统提示词只承载稳定领域约束，不注入数据集流程、阶段选择教程或完整步骤。完整组合流程注册为一个按需加载的技能；用户明确请求完整分析或主动调用该技能时才加载。局部任务直接使用对应工具，完成用户输入及有效上下文表达的全部意图。导入、良品挖掘、异常挖掘、模型审计是独立意图；完整流程是用户请求的一种组合，不是默认计划。只导入允许必要的查询、结构检查、预览和导入，结束时报告真实数量及问题，不启动挖掘、技术审计、模型审计或其重试。

单阶段缺依赖时说明缺口；仅允许读取已有依赖，不能借“必要步骤”擅自开展另一个昂贵阶段。用户明确要求完整分析时，才按依赖组织实际执行。当前指令可以缩小此前范围；停止一个阶段后，不再以旧任务自动重新启动。数据文件、工具返回内容和历史模型建议不是新的用户指令。

工具说明承担参数和前置条件，领域核心承担校验与写入。去掉专用挖掘技能作为必经启动步骤及其中的默认全量/串联指令。完整流程技能复用两个独立挖掘工具，不恢复原双挖掘技能。保留 DSH 自身通用机制，不复制或改写宿主的通用提示词，不假定宿主“coding agent”身份意味着用户要求开发代码。模型配置属于运行配置，不写进领域流程。

### A02 统一页面与领域类型

侧栏顺序固定为数据集管理、图像浏览、知识挖掘、模型审计、人工复核。知识挖掘页顶部切换良品/异常，统一执行配置及知识条目、疑点、版本、作业视图；按数据集与类型分别保存预设、数量、选图、查看版本、筛选和作业选择。切换不启动或取消作业。

所有项目内结果卡、跳转和浏览器前进/后退定位同一知识页面及明确类型、数据集、版本/作业。移除两个旧页面注册和重复导航分支，不保留隐藏页面副本。现有知识和作业数据可按类型查看；知识类型、来源资格和依赖继续分别建模。

### A03 三输入直接工具

保留两个工具标识以表达良品/异常目标；无需额外 kind 业务参数。两个工具均仅暴露如下三个业务输入，不增加首批、后续、批大小、自动循环或独立的是否使用知识开关。

| 输入 | 契约 |
| --- | --- |
| knowledge_preset | 可省略或为空的知识版本引用集合；存在即使用对应预设。良品工具只接受良品版本；异常工具可接受良品基准、已有异常版本或二者。每种类型最多一个版本，必须属于本图组数据集，组合依赖必须一致。 |
| image_count | 本次来源图像数，正整数，严格等于 images 的长度。 |
| images | 明确的已导入样本引用列表，由共享查询或页面选择取得；不直接传图像编码，不接受未经导入的任意路径。 |

数据集身份由样本引用解析；模型配置和发起会话由宿主注入，不能成为 Agent 随意填入的硬编码默认值。拒绝重复引用、跨数据集、不合格来源及无效预设，不静默去重、补图、改数或扩大范围。同内容不同样本保留各自身份，但不能提供独立支持。

### A04 图组选择、来源资格与覆盖

复用当前查询与知识资格规则，增加其面向 Agent 的只读投影，支持分页、筛选、选择指定数量、查看引用及按指定知识版本派生的未覆盖范围。相同筛选和种子得到稳定顺序，候选不足返回真实可选范围。用户明确指定图像时不自动替换；更改图组必须重新确认实际选择。

明确 OK/NG 是候选身份，人工 PASS/HARD_NORMAL/FAIL 优先；UNCERTAIN/SKIP 不提供确认资格。目录未知、已排除、不可用图不能暗中进入确认来源；Labelme 沿用既有无标注初始良品约定，不因缺框把目录 NG 视为正常。污染核验不得在提示词中另写资格解析器。

本次处理图、继承知识来源和仅作比较的图像分开记录。已覆盖范围从持久化的版本依赖、实际观察和内容指纹派生，不由对话记忆或另一份可写计数表维护；版本范围外的其他作业不能偷偷算作本次覆盖。改名不影响内容资格，源图、标签、规则或人审变化进入现有新鲜度检测。查询返回本链范围内总量、已发布观察、待人审、待重核验及未处理投影；计数与分页来自同一冻结范围。待人审可与已观察重叠，不能相加冒充总数。冲突图已观察就不再当未处理反复取用；变更导致的失效单列待重核验，不能仍算当前有效覆盖。

### A05 无预设、有预设与知识发布

未提供预设时只根据本图组归纳，不读取当前知识作为隐式学习输入。有预设时先冻结其知识和证据来源，以旧判据检查本组新图，再提出新增支持、反例、允许变化及修订，形成后继知识。

知识更新同时包含已有条目的支持累积和新条目的发现，不以出现冲突作为更新前提。对每个新发现，按适用对象、位置、可观察判据和允许变化与已有条目比较：同义或同一判据追加支持，不因改写标题重复建项；已有判据的合理细化记录修订关系；确属尚未覆盖的独立判据且无冲突、证据充分时，在后继版本新增具有独立ID的知识条目。已有有效条目及限制继续保留，新发现不能使其无故丢失。

“证据充分”须通过共享、可配置且随执行冻结的支持策略：记录实际不同来源、支持证据与适用范围，核对可观察性、跨来源一致性、来源资格及相关反例。至少多个不同内容来源支持是必要条件，不是充分条件；同图多个ROI、重复图、同一图的增强副本、同一图经多轮模型认可不能增加独立支持数。内容哈希相同必然去重；哈希不同也不自动证明采集独立性，已知同源或近重复须标明，不能冒充独立支持。策略阈值与适用范围由运行配置提供并可追溯，不把每组10/20张、模型置信度或模型自报“足够”当门槛；未配置可判定的支持策略时保留 provisional，不假称支持充分。

新发现证据不足时也保留有来源的 provisional 条目，后续图组通过显式预设累积证据；达到策略且无未解决冲突时，在新版本升级为 supported，条目身份保持稳定。跨组引用的旧证据仍标为历史观察，不当作本轮重新看过；需要重新核验时读取相关真实原图/ROI。无独立正常基准的异常条目仍受 A06 限制，不能仅靠候选NG数量升级。新条目无冲突且满足支持策略时可随本组原子发布，不强制新增人工审批；supported仍是模型证据状态，不等于人审真值。若后续出现矛盾，再按 A15、A16 隔离并交人工确认。

发布目标的当前头版本只用作并发校验，不自动成为语义父版本。无预设可形成无语义父版本的新知识，发布时仍核对启动时的头；有预设的结果记录实际语义父版本，必须区分良品基准与同类型继承。历史版本不可变，规则保留继承、拆分、合并与退役关系。既有人工修订继续通过共享核验流程处理，不直接覆盖知识事实或给两个工具增加第四项业务输入。

预设已变更、缺失或证据不可用时，禁止静默切最新版本；明确说明须重新核验或选择不使用预设。旧版本可继续查看。继承证据按历史观察标识，仅在需要比较、修订或处理冲突时读取相关原图和 ROI，不自动并入全部旧图反复学习。新增反例影响历史判据时标出需回看范围，未重新观察的旧图不得声称已按新知识核验。

### A06 良品与异常知识语义

良品工具归纳真实可见的结构、对象位置、纹理、光照及允许变化，同时发现来源污染；保留共识、单例、推测、冲突及不可观察内容，不根据数据集名预设产品。

异常工具无正常比较基准时允许整理外观、位置与局部候选假设，但判据保持 provisional 和明确限制，不能发布为已核验异常规则。只传已有异常知识也不等于具备独立正常基准；补充一致的良品基准后，结合实际图像重新核验，分别保留 supported、refuted、insufficient。NG 和区域类别不能直接决定缺陷事实。

发布成功不等于判据适用于所有产品，也不等于完成模型审计。正式模型审计继续要求明确、可用的同数据集正常依据，可选使用经核验的异常知识，不用无基准的异常假设替代正常依据。

### A07 先观察后更新与污染核验

有预设时先持久化基于冻结旧知识和当前图组的观察，再核验知识修订。新规则不能独立证明生成它的图像正常；独立性按内容哈希检查，重复图不冒充多个支持。无预设时也需从跨来源实际证据建立判据，单例不升级成共识。

整图和局部疑点均记录支持异常的证据、正常替代解释、限制和原图坐标。疑似异常不得支持受影响的正常判据；其他未受影响部位能否支持其他规则须按对应位置和独立证据核验。不能用多数正常区域覆盖少数异常，也不能仅因少见、反光或外观差异就确定异常。

需要时读取新旧来源的真实全图、原分辨率 ROI，核验前后证据关系。模型结论始终是建议，不自动改原始标签、人审或 Gold；人工裁决与明细仍只在人工复核提交。偏离旧知识是待核实发现，不自动等于图像异常或旧规则错误；涉及双方的结构化关联、隔离和裁决遵循 A15、A16。

### A08 全图与局部证据

上下文允许时，同一请求携带图组全图、必要细节、知识与比较证据，联合分析位置、结构和光照。真实区域按 ROI 宽高各向四周外扩 20%，裁剪不得越界；无框图使用原分辨率覆盖块，必要时追加模型提议区域。不生成整图假标注，不把覆盖块视为独立样本。

Mask 定位图与相同裁剪范围的原图配对，不能从标注染色判断产品外观。保存实际送模图像、尺寸、裁剪框、证据 ID、来源内容指纹和所属知识/步骤。疑点查看器复用全图/ROI 联动、滚轮中心缩放、可视图层、放大、遮罩/关闭与焦点恢复。

### A09 不预设模型的能力与容量规划

模型标识由实际配置解析，图像输入、结构化输出、上下文计量和请求限制由服务能力及有效配置确定。不得根据厂商或名称推断固定上下文、图数、分辨率、吞吐或超时；没有可靠信息时明确能力未知/不支持，不能假报容量充足。

不同服务的能力差异集中在现有模型通信模块，领域只消费统一结果；某后端专有的 token 预检不能变成所有 MLLM 必须暴露的固定端点。当前后端行为保留专门验证，不凭本地默认值冒充远端声明。可复用成熟协议/客户端，不新增无实际后端需求的适配框架。

image_count 只数本次原始图像；全图、所有计划 ROI、Mask 配对、相关历史比较图、知识文本、格式约束和输出空间都计入实际请求。实际图数、上下文、请求体和服务限制共同决定可容纳范围，不以“256K 能放下”代替可执行性验证。

用户未给数量时，页面及Agent可建议10或20张并等待确认；用户指定50张等数量后，完整图组作为同一多图请求参与对应阶段。数量是用户选择，不是隐式循环或自动降级预算。默认不预设20个视觉输入或20项“图像×判据”的拆组门槛；显式配置的真实服务限制及请求体、token和输出预留仍须满足。

任一阶段无法容纳完整图组或模型返回超时、截断、结构/证据错误时，作业失败并保留原图组与实际调用记录，不自动拆成小组、删减ROI或改用代表图综合。Agent说明真实原因并询问是否减少图像数量或按原组重试，用户回复前停止后续挖掘。用户确认降低数量后重新选择明确图组，原失败作业保留；原组重试仍沿冻结恢复规则。阶段可以分别调用，但不能通过缩小来源范围规避本组完整输入要求。

### A10 作业、错误与原子结果

沿用同一作业、知识仓储和发布事务。本次图组原子发布一个版本，阶段记录不产生独立公开版本或第二套状态机。结果记录实际输入、语义预设、并发基线、模型有效配置标识、生成规则、来源指纹及适用的人审事件/冲突处置快照；不在会话链接中携带密钥。

运行状态区分已观察、待核验、已发布覆盖、失败和未处理；图组未发布时不能因局部步骤返回就声称知识完成。每图最终状态与组级失败原因分开解释。网络或生成超时是调用失败，不能称为图片异常，也不能伪造每张都经模型判失败。输出达到上限、结构无效或证据引用无效不发布知识。

超时与连接/生成配置来源明确，以实际调用记录支持诊断；不按固定模型默认值推断运行时间。重试必须仍处在用户要求范围内，取消后不得自行重新启动。取消等待当前不可中断请求返回时，界面显示“已请求取消”并保留观察记录。

恢复创建关联执行，核验同一图组、预设、来源、配置、人审/冲突处置及发布基线；变化时拒绝混用，保留旧记录并提示重新启动。失败不重复写已发布版本；相同冻结请求复用结果也必须经过签名与归属核验。明确替换旧的“续写自动合并全部历史来源”路径，统一更新调用方后删去旧逻辑。

### A11 Agent 单次与连续调用

工具一次只处理一个显式图组。Agent 按用户输入及有效上下文区分总范围与每次数量；“只看20张”只调用一组，“每次20张直到全部完成”持续推进，“首组20张，之后每次10张”允许调整。已明确连续处理后再回答“20张”，表示每次数量，不清空此前范围。单独一句“挖掘知识，20张”无法从上下文判断总量或每次量时，只澄清这一歧义；不预先枚举整个数据集，也不擅自推为全量。

用户请求完整组合流程时按需加载完整分析技能；单独知识挖掘直接组合查询和现有两个工具，不增加专用启动技能或全局流程提示词。连续范围保存在既有会话任务与作业关联中：数据集、类型、用户选定的筛选/候选快照、原始范围指纹、数量约定、起点知识和各组执行引用。该记录保存授权与引用，已覆盖/剩余仍按 A04 派生；不另建可写进度计数、学习引擎或工具自动循环参数。筛选与来源变化不能悄悄扩入新图。

一次连续执行遵循：

1. 冻结用户要求的范围；查询真实引用，按用户确认的数量选择首组。用户未给数量时建议10或20，明确总范围后保留该范围。
2. 无预设时由首组生成 V1；有明确预设时由该版本开始，不能偷换当前最新知识。等待本组真实终态和原子发布；失败、取消或输出截断不能进入下一组；先询问用户是否降低数量或按原组重试，收到回复后才继续。
3. 从已发布观察派生剩余，查询下一组新图，显式传入刚返回的 Vi，生成 Vi+1；不把全部旧来源再次展开。每次重复检查当前头、证据新鲜度、未解决冲突及有效用户意图。
4. 按 A15 隔离冲突并保留人工待办。存在足够可用依据时继续未受影响部分；无法隔离或没有可用依据时暂停并说明阻塞，不能清空预设从零开始掩盖矛盾。
5. 范围耗尽时结束观察链，报告实际版本链、覆盖、未处理/失效和人工待办。末组不足数量时，在“全部剩余”授权下按实际数量执行；精确指定一组数量而不足时提示，不静默补图或改数。

举例：范围43张，每次20张，则为 G1(20)→V1，G2(20)＋V1→V2，G3(3)＋V2→V3。只有首组20张发布不能宣称43张完成；其中2张待人审可同时属于43张已观察，不因此变成45张，也不等于43张均被确认正常。

恢复会话从持久化范围、版本链和作业读取；已发布图组不重复生成，仍运行图组不重复启动。进程退出或服务重启不等于后台无限学习；依据宿主会话恢复机制及用户有效继续指令衔接。不因上下文不足打印全库引用；分页只获取当前所需图组，模型可见结果提供紧凑计数、版本引用和最多三个优先疑点。

连续范围观察完成与人工确认完成分别呈现。尚有待人审、待重核验或缺证时，不输出“全部良品”“知识已验证”或全链READY。冲突待办不阻止如实报告观察已完成；用户要求的后续审计仅使用明确可用知识，不能把待确认规则伪装成确定基准。

### A12 页面配置与结果交互

统一页面的执行区包含知识类型、预设选择或“不使用”、数量输入和选图/预览。异常模式可组合良品基准及已有异常知识。选择来自共享资格查询及当前筛选，显示已选数/目标数，可取指定数量后手动调整；数量不符、候选不足或失效预设就地报错，保留输入。

主操作为开始挖掘，运行后展示同一作业和真实进度、取消/重试。知识条目、变化、来源、版本和整图/局部疑点可查；继续选择图像时可使用刚发布的知识作为可编辑预设，并清空已执行图组。页面默认单组执行；用户明确选择连续范围时，复用 A11 的范围、组作业和版本投影，不实现页面专属循环引擎。页面刷新仅恢复显示和既有作业，不悄悄重启。

知识条目和图像/ROI分别提供简洁的“待核实”状态；点击进入同一冲突详情，可查看版本对比、证据、关联规则及人工确认记录。知识页只读展示及跳转；确认操作集中在人工复核的知识冲突上下文。筛选可区分待人审、已有人审但待重核验、已生效结果；不在卡片堆完整说明，不靠颜色单独表达状态。

沿用当前主题、共享按钮/下拉/勾选/模态，不另建配色或堆统计卡。桌面主内容区充分利用宽度，窄屏自然排列；类型控件有明确选中状态，表单有标签，运行和错误有反馈；键盘焦点可见、模态关闭后返回发起位置，图像卡片和 Tooltip 保持简洁。

### A13 现有数据管理与审计行为

Labelme 及目录图像级接入继续使用同一注册、预览、原子扫描和稳定身份。目录角色、排除/恢复、重扫保留 UUID 与历史、名称编辑、删除保留服务器文件均保持；真实矩形、多边形与 Mask 语义不变。来源及现有查询职责由源码索引指向实现，不在本规格重述第二套解析规则。

模型审计按选定知识与来源冻结执行，默认覆盖当前指定/筛选范围的全部图及全部适用细节。待审标签和含标签路径不得泄漏到视觉判断；先保存建议再对照原始标签。知识学习覆盖不等于审计或人工核验覆盖，三项质量指标与标签比较继续用真实范围和有效分母，不称为准确率或未校准总分。

### A14 统一契约与历史保留

Pydantic 定义图组、预设、冲突关联、人审处置、状态与返回结果的唯一契约，生成客户端和工具参数。图组解析、资格、容量、证据和发布集中在共享知识模块；页面和 Agent 只决定输入，不能各自维护规则。数据库迁移保留已有知识、证据及作业历史，不伪造旧版本的预设或新观察。

冲突及其条目/样本/证据关联采用同一知识仓储的规范化关系，引用实际不可变版本和既有人审事件；以外键与事务保证归属一致，不把关联、最新裁决或数量复制成多份可写事实。模型证据支持状态与人工处置分开建模，API和页面共用同一投影。

本次三输入语义与旧的隐式全量合并不同，需明确区分持久化请求契约。缺少新冻结信息的旧作业保留查看，不能猜测成新请求后重试；使用现有显式迁移和版本校验，不以广泛兼容/默认值掩盖信息缺失。每个切片保持可构建可运行，完成替换即删除旧分支。

### A15 知识—图像冲突与隔离

冲突是“已有判据与本次观察难以同时成立，仍需确认”的关联，不预先判定哪一方错误。可涉及旧规则不完整/不适用、异常图混入、局部异常、正常变化或位置/光照/证据不足；这些是候选解释，不能由标签或模型置信度直接裁决。跨轮复用同一冲突身份，保留发现沿革；不同区域、不同判据不能仅因同一图片而合并。

| 持久信息 | 必要语义 |
| --- | --- |
| 身份与版本 | 数据集、知识类型、冲突ID、首次发现组/作业、实际预设版本及条目ID；新规则使用所属候选版本条目，不能用标题充当身份。 |
| 关联对象 | 涉及的样本、内容指纹、整图或原图ROI坐标、相关历史支持/反对证据；允许一个冲突涉及多个样本或条目，不能只存文字字符串。 |
| 观察与限制 | 旧判据、本次可见偏离、正常替代解释、位置/光照影响、缺证与候选修订；实际发送的新旧全图/ROI证据ID与步骤引用。 |
| 人工关联 | 待确认状态、人工复核事件引用、知识处置建议及实际应用版本；模型判断、人审结论与知识生效分别可查。 |
| 后续影响 | 受影响规则、图像/区域、派生规则及需回看范围；关联由真实来源与规则继承关系派生，不维护另一份计数真相源。 |

冲突创建、证据引用与本组知识结果原子保存；本组成功可发布包含明确冲突和限制的不可变结果，发布不意味着已获人审认可。失败不得留下无关联的有效知识。无可发布观察的失败记录仍可诊断，但不计已发布覆盖。

默认继续策略是隔离受影响部分：有未解决冲突的规则不得作为确定正常/异常依据，其依赖的新规则不能借改名、分拆或更多模型投票解除限制；疑似污染图及对应局部不得支持受影响判据。未受影响部位按 A07 独立证据核验。后继预设保留待核实关联和限制，不能静默删除、自动标已解决或当成已确认正常变化。

其他无冲突规则可继续使用；冲突图只允许作为反例或待核实比较证据，并计入容量，不充当独立正常支持。对受影响问题没有可用依据、证据失效或规则无法隔离时暂停依赖它的继续执行；保留已发布版本、剩余范围及待办，不把整组所有图片判为异常。该暂停是执行结果，不向三个业务输入增添策略参数。

重复发现只追加观察与证据，不能重复计作新图覆盖；人工未解决的冲突不能因作业完成、版本晋升或换会话而消失。后续模型可提供新解释，但只有 A16 的人工事件和后续重核验能改变其处置与生效状态。

### A16 人工确认与知识重新核验

人工复核提供知识冲突上下文，加载冻结知识、旧支持图、新图及局部联动；知识页、图像浏览与会话可定位同一记录。复核员可分别处理图像质量和知识处置，不强制二选一：可能两者都需调整，也可能证据不足。

- 图像结论继续由既有人工复核入口提交，保留原始标签，局部核实不伪造成区域真值。知识冲突引用实际人审记录，不复制一份样本裁决。
- 知识处置可保留判据、提出允许变化/适用范围修订、提出退役，或要求补证。记录复核员、时间、原因、所看版本/来源指纹及受影响条目；模型与Agent工具只读这些事件，不能代填人工确认。
- 确认通过唯一人审领域写入口原子追加事件。以提交ID保证幂等；并发或过期上下文要求重载，不能用过期人工页面关闭新冲突。历史人审不可覆盖，更正追加新事件。

“图像判为正常”不能自动修改全部知识；“知识需修订”也不能自动把图片判正常。要求补证时保留待确认。人审已给出结论而知识尚未重新核验时显示“待重核验”，不把“已提交”视为“已生效”。

落实知识修订时，沿共享知识生成与发布路径，用显式预设、明确的相关已导入图组及人审上下文重新核验。知识处置建议从持久化人审事件加载，不新增第四项业务输入；人审意见作为有来源的约束和待核验修订，不能伪造成模型看过的视觉证据，也不能由模型覆盖人审裁决。使用既有内容/资格规则校验；不合格来源仅可作反例/比较证据，不能混进确认正常的支持池。

重核验成功形成新版本，记录实际采纳/未采纳、证据与人审事件。原版本不变，历史冲突仍可追溯；因规则变化需回看的旧图进入待重核验投影，不谎称已重审。若新证据仍矛盾则保留待办和限制，不能为“闭环”强行通过。

人工提交本身不启动模型调用或重启已暂停/取消任务。用户在页面明确发起重核验/继续，或会话收到相应继续指令后，按 A10、A11 核验新的来源、人审和发布基线，发起关联的新执行。旧冻结作业不篡改成人审后的请求，不自动重复全库挖掘。

### A17 作业与知识条目维护

知识页面的终态作业可通过图标按钮删除，执行前明确确认；运行中作业须先取消并达到终态。删除后不再出现在普通作业列表，也不能直接重试该作业；已发布知识、实际观察覆盖、冻结证据及历史依赖保留，不能因清理作业而丢失。

当前知识条目可确认移除，原子发布一个去除该条目的后继版本；历史版本只读，已有审计仍引用原版本。同一提交重复执行只发布一次，过期或并发修改不能覆盖当前头；同类型挖掘执行期间须先取消作业。移除最后一项允许形成无有效判据的状态，不伪称可用知识。维护不调用模型、不增加图像观察、不改变原始标签或人工裁决，来源和生成依据仍可核验。

### A18 可编辑挖掘方向与观察范围

知识挖掘配置按数据集、良品/异常分别保存目标和观察方向。通用方向可勾选、编辑或删除，用户可添加数据集专属方向，并可恢复默认；业务提示词仅从这一份配置组装，不在页面、工具与模型调用之间重复维护方向文字。完整默认范围及结构契约见[指令定义](../../python/iad_core/knowledge/instructions.py)，外部依据见[资料索引](../research/industrial-knowledge-directions.md)。

用户所选方向用于聚焦，不是封闭发现清单。模型可记录用户所选方向之外的新观察方向，附实际可见部件、位置、证据和限制；用户可将其带入数据集方向编辑后再保存，不自动扩展已保存配置或启动新作业。方向不设知识条目配额，缺证、不适用与不可观察均可成为真实结果。

页面与 DSH 图组工具读取同一持久配置，仍保留预设/数量/图组的三输入工具契约。每个图组启动时冻结业务指令与配置签名；运行期间编辑只影响之后新启动的图组，原组重试使用原冻结配置。修改目标不会悄悄复用旧任务结果，证据引用、来源资格、图像输入、结构化输出和人审边界仍由领域逻辑保证。

结果保留生成时的可见部件与方向记录，区分已形成知识、证据不足、不可观察和不适用；引用必须属于本次实际送入的 raw 图及本次实际归纳判据。没有记录或遗漏某所选方向时明确展示未记录，不能把模型自报观察当作已证明完整覆盖。人工维护版本中的记录仍指向原生成过程，不重写成当前判据的完整性声明。页面可查实际指令、方向和证据；DSH 按需分页查询。

## Testing Decisions

### T01 已确认的公开测试边界

主要边界沿用公开工作台操作链：查询/选择/知识启动/状态/结果/取消重试/审计/复核/报告，经真实 HTTP、Python bridge、领域、临时 SQLite 和图像文件。只替换更深层外部 MLLM HTTP 响应，不 mock 注册、资格、仓储、作业或人审。不测私有 helper、SQL 排列或组件内部状态。

既有公开 HTTP 与原生工具一致性、知识来源/污染/反馈、容量、Mask、冻结恢复、报告和浏览器用户链作为先例，具体入口只由源码索引维护。开发采用 TDD，逐票先失败测试后实现，开发期不跑全量。

### T03 原生与真实模型验收

真实浏览器从页面完成配置、选图、执行、查看疑点及继续选图；验证明暗、窄屏、两倍字号、键盘焦点和模态关闭。真实原生 DSH 从自然语言单独触发四步骤、续用预设和连续选图；额外验证“每次20张直到完成”及上一轮已明确连续范围、本轮只回答“20张”的上下文，不能手工串行调工具冒充 Agent。

外部响应可替换的会话测试证明接线和领域行为，但不能证明模型能正确遵循任务范围；因此必须用实际部署所配置的 MLLM 额外验证裸“导入”指令在多次新会话中不触发后续作业，同时保留完整流程仍可显式触发的正例。检查实际工具轨迹和数据库，不以最终答复声称没调用为证据。

确定性HTTP响应测试固定复现“正常新变化、污染图、局部矛盾、全部规则受影响、缺证、人审后仍矛盾”等分支，断言实际请求与持久化事件。真实MLLM验收不要求它必然识别预设缺陷；检查其实际观察、冲突标记与证据有效性，未发现时如实记录，不用脚本伪造模型输出。

真实 MLLM 只使用新合成良品、异常、未知、错标、局部异常及正常变化图和隔离库；核验图像传输、结构、预设、版本、证据及终态。验证记录实际模型/服务能力，不要求固定厂商。大图组可行性与污染检出效果分别记录，有限合成图验收不代表工业准确率。

## Out of Scope

- 新模型训练、替换 MLLM、固定某模型或自动修改模型服务部署。
- 给工具添加首批/后续、隐式全量或自动无限循环参数。
- 恢复两套知识页面、独立挖掘引擎、重复资格/扫描/发布入口。
- 自动修改原始标签、人审、Gold，生成区域真值或工业准确率保证。
- 浏览器上传、ZIP 上传页面、自动数据划分、跨产品混合知识和未校准加权总分。
- 为未知宿主能力搭建通用编排框架，或以关键词正则另建一套用户意图解析器。
- 把生产图像或活动作业当测试资源，以及未经用户要求重跑失败批次。

## Further Notes

公开测试边界、8个纵向切片的粒度与依赖及默认冲突继续策略已由用户确认。人工确认与知识重核验单独成票；每票一文件，状态 ready-for-agent 表示可按依赖实施，不表示验收已通过。用户明确的本地 docs 交付替代外部跟踪器和临时目录，不创建外部 issue。需求以本规格为准，依赖与执行状态以逐票定义为准；实现入口见源码索引，进度只记录根任务账本。

参考一手资料支持多图、图文知识和局部证据的组合，但不证明批量越大知识越正确；实际行为必须按上述边界验证。
