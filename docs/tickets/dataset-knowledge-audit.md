# 数据集知识与审计票据索引

行为与验收以[完整规格](../specs/dataset-knowledge-audit.md)及[统一 UI 设计](../design/workbench-ui.md)为准。本轮使用已确认的本地票据方式，一票一文件位于 `.scratch/dataset-knowledge-audit/issues/`；进度只记录于根 WORKLOG.md，下面仅定义交付顺序。

每票是可通过用户操作独立验证的完整切片。契约、存储与组件随首个使用流程交付，不单独拆成不可演示的水平层票；所有票先在公开边界写失败测试，再实现与定向验证。

涉及业务页面的票据均以 UI 设计 D01 的“各步骤的进度、结果与修改”为验收入口；DK-11 验证会话与页面的同源状态，DK-12 验证修改后的版本依赖与继续执行，DK-13 覆盖六步往返及历史回看。

| 票据 | 完整交付流程 | Blocked by |
| --- | --- | --- |
| DK-01 | 独立导航、数据集与图像浏览贯通 | — |
| DK-02 | 发布首个可追溯良品知识版本 | DK-01 |
| DK-03 | 良品污染识别与知识证据检视 | DK-02 |
| DK-04 | 基于正常版本挖掘异常并验证标注 | DK-03 |

DK-04 后两支可分别推进：Mask/联合审计，以及 DSH 技能；大图、人审、恢复、追问和知识迭代按真实依赖汇合。DK-13 汇总实际验收，不代替此前逐票验证。

票据文件名、可验收范围和依赖以逐票文件为准；规格负责需求，UI 文档负责视觉与交互，票据不复制整份规格。外部任务跟踪器不在本轮发布范围。
