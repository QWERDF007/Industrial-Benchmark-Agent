# 06: 按实际能力分组并完整覆盖图像

**What to build:** 用户给出10、20或其他图组时，工具按实际服务能力组织多图请求，保留全图、必要ROI及比较证据，不形成失控请求。

**Blocked by:** 03：可选预设续用与未覆盖查询

**Status:** completed

- [x] 对应 A08～A10、A12；不假定模型名、256K、图数或固定超时，能力来自实际配置/服务声明及有效预检，未知或不支持如实说明。
- [x] 默认项目上限20个视觉输入，合计全图/ROI/Mask/比较图，服务更小限制优先；原始图数不等于视觉输入数，不仅检查token或延长超时。
- [x] 知识文本、格式、输出预算、视觉token、请求体及图数共同规划，只在显式组内分组，不丢必要局部、原图Mask配对或图组来源。
- [x] 子记录及实际图像共同核验最终增量，未发送旧图不能称重看；最小证据无法容纳、结构无效或输出截断时不发布。
- [x] 两组不同能力经公开链检查实际请求和完整覆盖；页面显示来源图数/视觉输入数/步骤，传输或生成失败不伪装为图像质量裁决。

验证入口见[实现与验收索引](../../architecture.md)。
