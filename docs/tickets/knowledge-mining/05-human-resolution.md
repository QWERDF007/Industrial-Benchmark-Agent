# 05: 人工确认与知识重新核验

**What to build:** 复核员在人工复核确认冲突涉及的图片及知识处置，明确发起重核验后形成新知识，页面与会话能查到完整关联。

**Blocked by:** 04：整图与局部冲突证据及隔离

**Status:** ready-for-agent

- [ ] 对应 A07、A10、A12～A16；人工复核加载冻结条目、新旧证据及版本；知识页/图像/会话链接定位同一冲突，模型工具无人工提交能力。
- [ ] 图像裁决复用既有人审记录；知识保留/修订/退役建议或补证单独表达。样本PASS不自动证明规则，改规则不自动判图正常，允许双方均有问题。
- [ ] 唯一人审写入口按提交ID幂等追加事件，保留审核人/时间/原因/所看版本指纹。重复、并发及过期上下文有可观察结果，不覆盖历史，不复制样本裁决。
- [ ] 人审意见提交后但尚未应用显示待重核验；补证或仍矛盾保留待办，不能仅凭提交把规则标成supported或冲突清零。
- [ ] 用户明确启动后，现有三输入工具从持久化人审上下文冻结待核验修订，结合相关真实图像及预设发布新版本；实际人审事件参与签名，无第四项业务输入或另一套发布路径。
- [ ] 不合格来源仅作反例/比较，不能混入正常支持。应用记录可查实际采纳及证据，旧版本/标签/人审/Gold不变，受影响旧图进入待重核验范围。
- [ ] 确认不会自动发模型请求、恢复已取消任务或重跑全库；新请求与旧执行关联，来源/人审/头变化时不混用旧冻结输入。
- [ ] 经公开HTTP和真实库验证图像异常、正常变化、知识错误、双方问题、缺证及重核验仍冲突；浏览器完成一次人审→明确重核验→新版本→历史回看全过程。
