# 05: 按实际能力分组并完整覆盖图像

**What to build:** 用户给出10或20张等图组时，工具根据配置和实际服务能力组织多图请求，保留每张全图与必要细节，不因展开ROI而形成失控的大请求。

**Blocked by:** 03：可选预设与可追溯知识续用

**Status:** ready-for-agent

- [ ] 对应 A08～A10、A12；不假定模型名称、256K、图数上限或固定超时，能力从实际配置/声明及有效预检取得，未知或不支持时明确报告。
- [ ] 单次请求默认项目上限20视觉输入，计入全图/ROI/Mask/比较图，服务限制更小时从严；10来源展开大量ROI仍须拆分，不仅检查token或延长超时。
- [ ] 检查知识文本、格式、输出、视觉token、请求体及图数；只在显式图组内分组，保持图像/Mask配对、覆盖和子步骤证据关系。
- [ ] 跨组综合不能冒充重看未发送图像，必要图像参与规则和疑点核验；最小证据无法容纳或输出截断时不发布知识。
- [ ] 至少两组不同有效能力通过公开链验证实际请求边界与完整覆盖；页面显示来源图数/实际视觉输入数/步骤，网络超时不称为图像质量失败。
